# Заметки

SPA для заметок со списками задач. Nuxt 4, TypeScript в strict-режиме, Pinia, SCSS.

Две страницы: список всех заметок и редактирование одной. Данные лежат в localStorage.

## Запуск

Через Docker:

```bash
docker compose up
```

Приложение поднимется на http://localhost:3000. На старом Compose v1 команда называется `docker-compose up`.

Локально:

```bash
npm install
npm run dev
```

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | дев-сервер |
| `npm run build` | продакшен-сборка в `.output` |
| `npm run preview` | запуск собранного приложения |
| `npm test` | юнит-тесты |
| `npm run typecheck` | проверка типов |

## Структура

```
app/
  components/   переиспользуемые компоненты, включая модальное окно
  composables/  горячие клавиши отмены и повтора
  pages/        список заметок и страница редактирования
  stores/       стор заметок на Pinia
  types/        типы предметной области
  utils/        работа с localStorage и история изменений
tests/          юнит-тесты стора, хранилища и истории
```

## Решения

**Рендеринг.** `ssr: false` — по заданию это SPA, а данные лежат в localStorage, которого на сервере нет. Серверный рендер выдал бы пустой список с последующей подменой на клиенте. Индексация поисковиками для приложения с личными заметками не нужна.

**Хранилище.** Синхронизация написана руками, без плагинов персистентности — так требует задание. Запись отложена на 400 мс: localStorage синхронный, и писать на каждое нажатие клавиши значит сериализовать все заметки десятки раз в секунду. Чтобы отложенная запись не потерялась при закрытии вкладки, она принудительно сбрасывается по `pagehide` и при уходе страницы в фон.

Сохранённые данные помечены версией схемы. Если в хранилище окажутся данные более новой версии — приложение покажет пустой список, но не станет их портить.

**История изменений.** Хранятся не копии заметки, а обратимые патчи: что изменилось, каким было и каким стало. Одна функция применяет патч вперёд и назад, поэтому отмена и повтор — это одна и та же операция в разные стороны. Глубина — 50 шагов, любое новое изменение очищает ветку повтора.

Непрерывный набор текста в одно поле — одна запись в истории: значение запоминается при фокусе и сравнивается при уходе из поля. Отметка чекбокса, добавление и удаление пункта записываются сразу, они дискретны по своей природе.

**Горячие клавиши.** Ctrl+Z и Shift+Ctrl+Z (на macOS — с Cmd) работают на странице редактирования, но только когда фокус вне текстовых полей: внутри поля отмена должна откатывать набранный текст, а не всю заметку. Клавиша определяется по `event.code`, а не по `event.key`, чтобы отмена работала и в русской раскладке.

**Черновик.** Незасохранённые правки пишутся под отдельным ключом, привязанным к заметке. Если после перезагрузки они отличаются от сохранённой версии, приложение предложит их восстановить. Черновик стирается при сохранении, отмене редактирования и удалении заметки.

**Удаление в другой вкладке.** Приложение слушает событие `storage`. Если заметку, открытую на редактирование, удалили в соседней вкладке, появится окно с предложением вернуться к списку. Без этого нажатие «Сохранить» воскресило бы удалённую заметку.

**Пустые значения.** Заметку нельзя сохранить без названия — кнопка сохранения неактивна. Пустые пункты списка при сохранении отбрасываются, у остальных обрезаются пробелы по краям.

**Несуществующая заметка.** Прямой переход по URL к удалённой или выдуманной заметке показывает понятный экран со ссылкой на список.

**Модальные окна.** Свои, без UI-библиотек: фокус запирается внутри окна, Escape закрывает, после закрытия фокус возвращается на элемент, который окно открыл. Все подтверждения идут через них, `alert` и `confirm` не используются.

## Тесты

Покрыты стор, работа с localStorage и логика истории изменений — то, где живёт вся нетривиальная логика. Компонентных тестов нет, задание их не требует.

```bash
npm test
```
